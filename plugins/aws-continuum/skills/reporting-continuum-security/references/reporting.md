# Report evidence and renderer contract

The agent collects public API evidence and authors Markdown. The renderer owns validation, escaping and brief v2 presentation. The offline source checker owns repeatable snippet comparison. Neither acquires AWS data, executes application code or records decisions. There is no MCP server or snapshot helper. Status must not generate replacement executables or launch a browser.

## Authoritative evidence

- Apply the shared AWS safety prelude before every read. List all finding pages, then group by `createdIssueId` across scans. Unlinked findings remain individual candidates. The newest row decides; discarded newest rows cannot resurrect older verdicts. Hydrate one newest finding per issue, not a title or file/category representative. Preserve unknown or pending newest reads without historical substitution.
- After hydration, merge issues only if the newest findings have identical normalized `vulnerableCode` in the same file. Use the source checker's `snippetIdentity`, which removes presentation labels, numeric line prefixes and whitespace, while retaining code identity including punctuation. The newest constituent finding decides the merged flaw. Retain all constituent IDs in that one flaw row. Old pre-dedupe issues may inflate counts; disclose that in Limits.
- `validation.verdict` is authoritative. TRUE_POSITIVE gets **Open** or **Probably fixed** assessment. Only Open flaws supply paths, fixes and the Validated issues register. BENIGN_TRUE_POSITIVE is real but mitigated. FALSE_POSITIVE gets one ruled-out row per flaw. CONFIRMED status, issue creation and preview availability do not override verdicts.
- Select code in order: matching Git workspace, readable shallow default-branch clone outside the workspace, readable S3 archive with the verified expected bucket owner, then scan-only. Record source branch/revision or archive age and dirty state. Never use an unrelated workspace or a privileged alternate identity. Safely extract archives and remove only owned temporary copies.
- `check-current-code.mjs` is a filter: only every significant line unchanged at its cited position and in order in every location means **Open**, basis **code unchanged**. Other checks with usable source return **Needs review**, with location status, fuzzy match ratio and best-matching range (or null). Fuzzy matches only locate evidence. The filter never outputs Probably fixed; no usable source or snippet retains scan-only Open.
- For every Needs review flaw, the agent reads current source and available `git log` and `git diff`, including deletion or rename history and replacements. Never follow unsafe paths; record gaps. Decide Open or Probably fixed with a one-line Basis citing file and lines or deletion history. When unsure, keep Open. Needs review is not a final state. Scan non-recurrence never proves a fix; Probably fixed still needs a regression test.
- `issues.json` is `{ "items": [...] }` for reported flaws only. Open flaws use fetched issue records; other rows may use compact issueId-only references. Every scoped ID appears in a flaw row. Limits gives historical repeat counts, never historical ID lists.
- Get issues and list artifact metadata only for Open flaws. Stop once a PATCH preview is found or pages end. No artifact bodies or non-Open histories are needed for status. Retain ID, type and `contentSizeBytes`, failures and unchanged raw responses; get fields win on overlap with conflict provenance retained. Preview availability is not application, testing, merge or deployment.
- Severity comes from fetched issue records. Exact-code merged rows use the highest fetched severity and disclose conflicting severities. The severity bar counts unique constituent Open issue IDs at their individual severities; it can differ from flaw counts.
- Preserve complete `synopsis`, `summary`, `detailedDescription`, `mitigation`, `validation.rationale` and `validation.severityAdjustment` in unchanged ignored evidence. Never invent a description field. Ruled-out **Reason** summarizes the decisive rebuttal and prerequisite and should stay within 25 words, not the allegation, generic classification or first rationale sentence. Read the complete rationale; leave the full rationale in Continuum and raw evidence.
- Scanner, validation and issue lifecycles are separate. SUCCEEDED is not the end. Record latest success and latest attempt separately, current work, unknowns and failed reads. Derive the enclosing collection window from the complete request ledger including STS and failures. State actual finding/issue/artifact request counts, any broader hydration exception and why, budget overruns and incomplete capture.

## Local scripts

```bash
node <skill-directory>/scripts/check-current-code.mjs newest-findings.json <source-root-or-dash> assessments.json
node <skill-directory>/scripts/render-report.mjs report.md issues.json out.html
```

Node 20 or newer is enough; installed copies need no npm packages. The first input is an array of newest hydrated findings. Use `-` with no source. Caller guidance must establish source identity and completeness; the checker does not prove either. It returns state, basis and location read/match evidence. It cannot prove a security fix, changed semantics or deployed safety.

Only these two runtime scripts ship. Renderer source, CSS, boot, parser, build and browser inputs stay in the development checkout. The locked esbuild and marked packages build the renderer with Mermaid's real flowchart Jison grammar, not its drawing engine for Node. Browser Mermaid, CSS and enhancements are embedded in the bundle and standalone HTML. No network, fonts, styles or scripts are fetched. Flowchart syntax is checked, not truthful topology, complete coverage or mathematical minimality.

Checks reject a missing first Summary or code in Summary, missing scoped IDs, absent paths/fixes registers, invalid path states, unknown blocked paths, missing State/Basis, unresolved Needs review flaws, non-Open Validated issues, mismatched Probably fixed states, missing fetched Open issue severity, merged-row severity disagreements, invalid Ruled out structure and invalid Mermaid syntax or author styling. Probably fixed accepts the agent's nonempty current-code evidence Basis. Summary and Ruled out reason word limits, scan-absence prose, IDs in Limits and diagram width warn; they need no rendering fallback. Uncovered paths still warn and do not become closed. Errors exit 1 before writing HTML or a success Summary; warnings alone exit zero. The authored Summary and absolute HTML path print after success.

The required exact `### Validated issues` register begins with Severity. An explicitly empty table means zero; a missing register is an error. IDs use `Title (\`issue-id\`)`. Probably-fixed, mitigated and ruled-out IDs never enter the severity bar. The short bold current-state headline should fit two lines at 412 CSS pixels; dates, failures and exposure detail follow in the paragraph. Default fix wording is proposed covering fixes for modeled paths, not an unproved smallest set.

Raw HTML, event attributes, images and unsafe links become inert text. Allowed links are trustworthy HTTPS, local anchors and safe repository-relative paths. Mermaid uses strict mode. CSP: `default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:; base-uri 'none'; form-action 'none'`. Service text is never interpolated into executable scripts.

## Package validation

Root `npm test` runs static manifests, generated-source hashes and offline tests. The development server package additionally runs Chromium checks. Captured otel/selfscan fixtures retain their captured inventories and historic Open basis; they do not assert fresh source checks. Synthetic state, reason and escape fixtures stay separate from captures. Browser tests cover desktop, inner and cover in both orientations, themes and JavaScript-off. Emulation is not physical-device or screen-reader certification.

`tools/audit-saved-report.mjs` is a development-only offline audit using saved JSON. It counts issue-unit finding hydration, exact-code merges and available assessments. Missing newest bodies remain unknown. Its explicit source-mismatch override is **offline only**, never permitted in live reporting.

Never commit a customer's `.continuum/reports/`. Raw evidence and shareable reports can be sensitive. Publishing or applying fixes requires separate approval.
