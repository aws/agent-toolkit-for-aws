# Report Decision Core — Azure layer

## Load order

1. **Load `references/vendored/report/report-decision-core.md` first.** That vendored copy is the canonical, cloud-agnostic decision core — the section model and stable IDs per mode (including `ai_only`), the decision-mode contract, verdict typography and metric hierarchy, cost labeling and the `data-cost-key` anchors, readability, CSS and accessibility, the draft footer. It lives inside this skill; read no other skill's file.
2. **Then apply this file.** It supplies the values the canonical writes as `⟨parameter⟩`, Azure's Operational Changes rows, and the Azure-only add-ons. Nothing here overrides a canonical rule; where this file is silent, the canonical rule applies unchanged. Where the canonical and `$PLUGIN_ROOT/scripts/validate-migration-report.py` disagree, the validator wins.

Other files in this skill cite the decision core by its legacy section numbers. They map to the canonical headings as: Section 0 = Decision summary · 0b = Share With Your CFO · 1 = Current Stack Overview · 1b = Estimated AWS Monthly Run Rate (`exec-tco`) · 2 = Recommended AWS Architecture · 2b = Architecture diagram · 3 = Cost Comparison · 3b = What-if scenarios · 3c = Cost Optimization · 4 = Security & Cost Guardrails · 5 = Operational Changes · 6 = Timeline · 7 = Top Risks · 8 = What this assessment rests on.

### Decision CTA

`<section id="decision-cta">` — "**Ready to execute?** Say \"generate the Terraform, migration scripts, and the migration guide\" and I'll produce the full execution pack (Terraform, migration scripts you run yourself and that are dry-run by default, the migration guide with its rollback and verification sections, and the migration report) from this same analysis." On an AI-only run (no `azure-resource-inventory.json`) there is no Terraform or migration guide to promise: say \"generate the migration artifacts\" and name the artifacts the gate's `[C]` label lists (estimate-assemble.md) instead. Plus the canonical fixed line: "This decision report was generated without execution artifacts; the full migration report replaces it if you proceed."

### Validator invocation

Default contract, no `--profile`.

```sh
python3 "$PLUGIN_ROOT/scripts/validate-migration-report.py" "$MIGRATION_DIR/migration-report.html" --mode full --migration-dir "$MIGRATION_DIR" --estimation-infra "$MIGRATION_DIR/estimation-infra.json" [--estimation-ai …] [--aws-design …]
```

Decision mode: the same command against `$MIGRATION_DIR/decision-report.html` with `--mode decision`. AI-only run: `--mode ai_only` with `--estimation-ai` and no `--aws-design` (there is no design artifact on that path). Pass the estimation and design files when they exist so the cost-anchor, share, security-teaser, and Cost Optimization gates fire; `--migration-dir` is required on every real run. `REPORT_OK` from this one validator is the gate — this skill has no add-on validator for the report.

## Service mapping table

Operational Changes rows (canonical § Operational Changes). Only render rows whose Azure source type is PRESENT in the design artifact — check each `azure_type` / `aws_service` pair and skip unmatched rows entirely.

| Azure Service                | AWS Service                 | What stays the same                               | What's new                                                                                                        |
| ---------------------------- | --------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| App Service / Container Apps | Elastic Beanstalk / Fargate | Managed web/containers, auto-scaling, pay-per-use | One App Service Plan maps to one Elastic Beanstalk env (fan-in preserved); ALB for HTTP routing; ECR replaces ACR |
| Azure SQL / Flexible Server  | RDS / Aurora                | Managed DB, automated backups, PITR               | Parameter groups replace server parameters; Security Groups replace firewall rules                                |
| Blob Storage                 | S3                          | Object storage, lifecycle policies, versioning    | Bucket policies replace RBAC/SAS; CloudFront needed for public CDN                                                |
| Azure OpenAI                 | Bedrock                     | Managed API, pay-per-token                        | IAM-based access (no API keys); SDKs differ (Azure OpenAI SDK path maps to the Bedrock/OpenAI adapter)            |

## Azure add-ons

Declared add-ons on top of the canonical contract — rules that exist only because the source cloud is Azure.

- **AI-bundled total (`exec-tco`):** when the user stated a single Azure monthly total that bundles AI/Cognitive spend (Azure OpenAI, Document Intelligence, etc.) — because `estimation-ai.json` is reported as a separate artifact from `estimation-infra.json` — do **not** place that bundled total beside the AWS infrastructure figure as if comparable, and do **not** render a savings %. Show it with the `⚠ not comparable` chip and one line: "your stated Azure total includes AI spend, which is estimated separately here; compare against the combined infra + AI run rate, not infrastructure alone."
- **`baseline_not_invoiced` label (Cost Comparison):** when `current_costs.source` is `baseline_not_invoiced` (the Azure baseline came from a rung other than a Cost Management export — see `estimate-infra.md` Part 1), label the figure "Azure baseline not invoiced — derived from resource configuration, not billing" and treat it as **not comparable** to a user-stated spend band (apply the canonical not-comparable rendering).
- **Stale scenario rows (What-if scenarios):** rows whose manifest carries `stale: true` are labelled "(stale — priced before a decision-gate correction)". Only this skill's scenario schema has the `stale` field.
- **What-if columns (What-if scenarios):** the comparison table's columns are the ones `references/phases/workshop/workshop-compare.md` defines; keep the two in step when either changes.
- **Startup-program artifact check:** _Full mode only:_ after Generate, run `scripts/validate-startup-program-artifacts.py --migration-dir $MIGRATION_DIR`. (Decision mode: the Activate wording rules above still apply to the rendered content; the script runs when the Generate artifacts it checks exist.)
- **AI-stale complexity (Timeline, full mode):** when infrastructure was classified Large solely because AI coexists, treat that as an invalid stale classification and re-run complexity sizing before rendering the timeline.
- **Deferred-services example:** the `exec-tco` deferred-services exclusion names Synapse / Data Factory as its example.

## Declared exceptions

None. azure-to-aws follows the default contract: the validator's default required-ID sets in `decision`, `full`, and `ai_only` mode, no `--profile`, every canonical section rendered under its canonical trigger. Any future shape divergence must be declared here and in `SKILL_PROFILES` of the shared validator, never silently.
