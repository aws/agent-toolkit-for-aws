# Report Decision Core — Render layer

## Load order

1. **Load `references/vendored/report/report-decision-core.md` first.** That vendored copy is the canonical, cloud-agnostic decision core — the section model and stable IDs, verdict typography and metric hierarchy, cost labeling and the `data-cost-key` anchors, appendix lettering, readability, CSS and accessibility, the draft footer. It lives inside this skill; a render-only install reads no file from any other migration skill.
2. **Then apply this file.** It supplies the values the canonical writes as `⟨parameter⟩`, the Render-only add-ons (the migration-execution sections, the executive add-ons after the cost table, and the render-local validator's rules), and the declared omissions. Nothing here overrides a canonical rule; where this file is silent, the canonical rule applies unchanged. Where the canonical and `$PLUGIN_ROOT/scripts/validate-migration-report.py` disagree, the validator wins.
3. **Only full mode exists — the canonical's decision-mode contract does not apply.** This skill has no Decision gate and writes no `decision-report.html` or `DECISION.md`: after Estimate, `estimate-assemble.md` offers **Done for now** or **Generate**, and the report is rendered only by Generate (`generate-artifacts-report.md` Step 1). Every canonical rule applies in its full-mode form; there is no _Decision mode:_ override to consult. The report is rendered **fresh from the artifacts** on every Generate run; recalled values from the chat transcript are never a source.

Other files in this skill cite the decision core by its legacy section numbers. They map to the canonical headings as: Section 0 = Decision summary · 0b = Share With Your CFO · 1 = Current Stack Overview · 1b = `exec-tco` · 2 = Recommended AWS Architecture (`exec-targets` here) · 2b = Architecture (`exec-architecture`) · 3 = Cost Comparison · 3b = What-if scenarios · 3c = Cost Optimization · 6 = Timeline · 7 = Top Risks · 8 = What this assessment rests on.

### Validator invocation

Two validators gate the report, both run in the main window with absolute paths (`generate-artifacts-report.md` Step 5):

- `$PLUGIN_ROOT/scripts/validate-migration-report.py` (`--mode full`, with `--estimation-infra`, `--aws-design`, and `--migration-dir`) is the structure/content gate: required section IDs and order, the CSS shell, verdict and metric-hero markup, the risk table, assumptions after risks, appendix depth and section IDs (the validator does not check appendix letters), readability, accessibility, the glossary, and the shared cost anchors.
- `$SKILL_BASE/scripts/validate-render-migration-report.py` (`--migration-dir`) is the render-only pass: the sections, terms, target rows, accounting, ledger reconciliation, `delta` anchor, unavailable-baseline literal, optimized/premium anchor presence, projected/scenario cost equality, `appendix-assumptions`, the Appendix G baseline-resource cross-check (`SECTION_APPENDIX_SECURITY_MISSING`, `SECURITY_BASELINE_RESOURCE_MISSING`), and exclusions listed below.

Both must print `REPORT_OK`. A report that fails either is renamed `migration-report.incomplete.html`; it remains available for diagnosis but MUST NOT satisfy Generate `_produces` or completion. There is no skip-and-complete path.

## Declared omissions

- **No Activate callout:** no `startup_program_status` is collected and no `STARTUP_PROGRAMS.md` is written, so the canonical startup-credits callout, apply link, and tier rules never fire.
- **`exec-tco` never rendered:** this skill never writes an AI estimate (the AI track is `deferred_shared_ai_engine`). If a future run carries both estimates, the canonical `exec-tco` rules apply unchanged.
- **Canonical security-teaser trigger never fires:** `projected_costs.breakdown.security_baseline` never exists in this skill's estimate, because estate-wide costs attach to design mappings (`estimate-infra.md`: no separate estate-wide lines). The teaser is rendered on the declared add-on trigger below instead.

## Render add-ons

Declared add-ons on top of the canonical contract, each enforced by the render-local validator unless noted.

- **Deferred AI flag (Decision summary):** when `estimation-infra.json` → `ai_track.status` (or the design's AI track) is `deferred_shared_ai_engine`, add a callout under the verdict stating that the AI workload is assessed separately by `bedrock-migration-assessment` and carries no target, cost, model, adapter, or Terraform in this report. This does **not** block the phased migration of the infrastructure.
- **Empty `stay_if` (Decision summary item 5):** when `stay_if` is empty, render one line saying no whole-stack stay condition was identified — never an empty list. The "Stay entirely if" heading protects the deferred AI workload or an unsupported Workflow from reading as a whole-stack stay.
- **`exec-targets` (Recommended AWS Architecture, REQUIRED):** columns Render resource, Kind, AWS service, Disposition, **How we chose this**. One row per `aws-design.json` mapping; each row is `<tr data-source-resource-id="…" data-aws-service="…">` carrying the exact mapping values, and the row's visible text names the AWS service — the render-local validator compares the row set to the design exactly (`TARGET_MAPPING_MISMATCH`, `TARGET_VISIBLE_TEXT_MISMATCH`, `TARGET_ROW_ATTRIBUTES_INCOMPLETE`). For every ECS on Fargate mapping, state whether it is **Express or standard** and quote `aws_config.ecs_mode_reason`.
- **`exec-architecture` (REQUIRED always):** the plugin-root validator requires it only when the design has clusters; this skill requires it always. Prose or a structured diagram covering, in plain language: build-once ECR image promotion by digest, private ingress (ALB/CloudFront in front, services in private subnets unless the design placed an Express service in public subnets), managed PostgreSQL (RDS) and Valkey (ElastiCache), EFS for persistent disks, Step Functions for a supported Workflow, and tagged, isolated per-environment stacks. Name the deferred AI surface. Required phrases: `build-once` (or `build once`), `private`, `managed`. Source: `aws-design.json`, `render-resource-clusters.json`.
- **Cost anchors (Cost Comparison):** `aws_monthly_optimized` and `aws_monthly_premium` are **required** alongside the canonical `current_monthly` and `aws_monthly_balanced`: exactly one anchor each inside `exec-costs` (the estimate schema always carries both values; `COST_AWS_MONTHLY_OPTIMIZED_MISSING` / `COST_AWS_MONTHLY_PREMIUM_MISSING`). The estimate must also satisfy `projected_costs.aws_monthly_premium` / `aws_monthly_balanced` / `aws_monthly_optimized` = `scenarios.premium` / `balanced` / `optimized` `.known_cost_monthly_usd` (`COST_AWS_MONTHLY_PREMIUM_SCENARIO_MISMATCH` / `COST_AWS_MONTHLY_BALANCED_SCENARIO_MISMATCH` / `COST_AWS_MONTHLY_OPTIMIZED_SCENARIO_MISMATCH`). The render-local `data-cost-key="delta"` anchor (value `rightsizing_delta.monthly` = like-for-like minus Balanced, rendered as `+$45`; positive means right-sizing saves) sits in the like-for-like comparison row's "vs Balanced" cell (`COST_DELTA_MISSING` / `COST_DELTA_SOURCE_INVALID` / `COST_DELTA_MISMATCH`). The render-local `data-cost-key="like_for_like_monthly"` anchor (value `scenarios.like_for_like.known_cost_monthly_usd`, whole dollars half-to-even) sits in the same row's "Monthly (USD)" cell, exactly one inside `exec-costs` (`COST_LIKE_FOR_LIKE_MONTHLY_MISSING` / `COST_LIKE_FOR_LIKE_MONTHLY_SOURCE_INVALID` / `COST_LIKE_FOR_LIKE_MONTHLY_MISMATCH`). The unavailable-baseline literal is checked as `COST_CURRENT_MONTHLY_MISSING` / `COST_CURRENT_MONTHLY_UNAVAILABLE_TEXT_MISMATCH`. Each anchor sits on a rendered element inside `exec-costs` itself — not in an HTML comment. Whole dollars are rounded half-to-even (313.5 → `$314`, 277.8 → `$278`, 358.5 → `$358`).
- **Footnote additions (Cost Comparison):** the canonical footnote reads _Only one Terraform configuration is generated (Balanced-aligned, right-sized baseline)_, and states that human labor is excluded (`migration_cost_considerations.human_labor_monthly_usd` is null). When any scenario or the like-for-like block has `is_floor: true` or non-empty `unpriced_line_ids`, say the total is a **known-cost floor** and name the unpriced lines.
- **Top Risks count:** up to 3–5 highest-severity risks (the canonical says up to 3), never empty; sources per ⟨risk_sources⟩.
- **Cost Optimization (`exec-optimization`, with Appendix B.1):** rendered from `estimation-infra.json` → `optimization_opportunities[]` (one row per commitment bucket, per `estimate-infra.md`) and `scenarios.optimized.commitment` (the eligible subtotals, mid-point rates and per-line rounded discounts the posture table quotes), following `generate-artifacts-report.md` Step 2.5. The Compute Savings Plan row stays percent-only until a 30–90 day usage baseline exists. The Database Savings Plan row carries a dollar figure only when a line passes the Generation 7+ gate; when every recorded class is pre-Generation-7 it claims no saving, names the ineligible classes and says a Generation 7+ class would qualify. The Appendix B.1 credits caveat appears once, directly below the B.1 table: promotional or AWS Activate credits do not cover the upfront cost of Reserved Instances or Savings Plans (Partial or All Upfront) and apply only to the ongoing discounted rate.
- **Security teaser (`exec-security-teaser`):** rendered whenever `terraform/baseline.tf` is emitted (always, for this skill), although `projected_costs.breakdown.security_baseline` never exists here (see Declared omissions). Rows: GuardDuty, CloudTrail, Budget alerts with the canonical indicative ranges and the budget `limit_amount` the baseline wrote; the section says none of them is a line of the estimate, states whether the compliance add-on was generated (`preferences.json` → `global.compliance`), and points at Appendix G. Control names only — no artifact filenames or Terraform addresses in the executive flow.
- **What-if (`what-if-scenarios`):** rendered when `scenarios/index.json` lists two or more scenarios. The index carries its manifests inline (no `manifest` path field); Region ← `global.aws_region`, HA ← `global.availability`, Compute ← `global.management_model` (this skill has no Kubernetes knob), Arch ← `global.cpu_architecture`, each overlaid by the scenario's `preferences_subset`; costs and complexity ← `estimation_summary`; the active row carries `class="active-scenario"`; `calculator_url` is always null, so no calculator link.
- **Section order:** `exec-costs` → `exec-optimization` → `what-if-scenarios` → `exec-security-teaser` → `exec-timeline`; `exec-assumptions` sits after `exec-risks`, immediately before the migration-execution sections (which precede the appendices).

### Render-specific required sections

Beyond the default `full` set, this skill requires each section below exactly once, non-empty, and linked from the TOC (render-local codes `SECTION_<ID>_MISSING` / `_DUPLICATE` / `_EMPTY`, `TOC_RENDER_SECTION_MISSING`). The phrases in `code` are the terms the render-local validator looks for in each section's rendered text (case-insensitive; one alternative per group suffices).

1. `exec-architecture` — above. Terms: `build-once` or `build once`; `private`; `managed`.
2. `exec-targets` — above: one `<tr data-source-resource-id data-aws-service>` row per design mapping with the service in visible text.
3. `migration-data` — PostgreSQL full-load/CDC procedure, Key Value transition, writer quiescence, integrity checks, and source retention. Terms: `postgres`; `Database Migration Service` or `pg_dump`; `quiesc`; `integrity`; `source retention`.
4. `migration-storage` — EFS pre-copy/delta transfer for `/var/data`, ownership/permissions/locking checks, quiescence, integrity, and rollback. Terms: `efs`; `/var/data`; `pre-copy`; `delta`; `ownership`; `permissions`; `integrity`.
5. `migration-deployment` — build-once ECR digest promotion, serving-deploy identity, auto-deploy state, immutable rollout, and rollback lineage. Terms: `ecr`; `digest`; `serving deploy`; `auto-deploy`; `rollback`.
6. `cutover` — prerequisites, certificate readiness, DNS TTL, writer quiescence, traffic shift, and acceptance checks. Terms: `dns`; `ttl`; `certificate`; `traffic`; `writer quiescence`.
7. `rollback` — rollback triggers, writer fencing, DNS/traffic restoration, target cleanup limits, and retained Render source. Terms: `source retention`; `render`; `restore`; `dns`; `writer`.
8. `verification` — concrete endpoint, database, cache, disk, worker/cron, and Workflow checks. Terms: `endpoint`; `database`; `cache`; `disk`; `workflow`.
9. `deferred-surfaces` — the exact `deferred_shared_ai_engine` warning paragraph and every `conditional_workflow_generation_unsupported` warning. Deferred work is never represented as generated (`AI_DEFERRED_STATE_MISSING`, `AI_DEFERRED_WARNING_UNEXPECTED`, `WORKFLOW_LIMIT_MISSING`). This section (and the appendices) may name artifact filenames; `decision-summary` and the `exec-*` sections may not.
10. `appendix-accounting` — heading "Appendix A.1 — Generation Accounting" (the canonical A.1 slot; the `.1` keeps the shared letters A–J from shifting): design/generated/consumed-topology/deferred/unsupported counts and all source rows. The section carries `data-accounted-count` equal to `generation-warnings.json` → `accounting.accounted_count` (`REPORT_ACCOUNTED_COUNT_MISMATCH`).
11. `appendix-security` — when `terraform/baseline.tf` is emitted, Appendix G must exist and its Terraform column must name every `resource "<type>" "<name>"` address the file declares, written as `<type>.<name>` (`SECTION_APPENDIX_SECURITY_MISSING`, `SECURITY_BASELINE_RESOURCE_MISSING`). The check reads `terraform/baseline.tf` from the report's own directory and is inert when the file is absent (baseline opted out).
12. `appendix-assumptions` — Appendix I, Assumptions, Exclusions, and Validation. The render spec requires it; the shared default `full` set treats it as optional, so the render-local validator enforces it (`SECTION_APPENDIX_ASSUMPTIONS_MISSING` / `_DUPLICATE` / `_EMPTY`, `TOC_RENDER_SECTION_MISSING`).

### Cross-artifact truth

The render-local validator compares rendered targets to every `aws-design.json` mapping, accounting to `generation-warnings.json`, and Appendix G to the `resource` addresses of `terraform/baseline.tf`; the plugin-root validator compares cost anchors to `estimation-infra.json`. The generation ledger classifies every design source exactly once as generated, consumed topology, deferred, or conditionally unsupported. AI is represented only by the exact deferred state; Workflow Terraform is represented only when its semantics are supported and validated.

The report is a customer artifact. It never contains source secrets, environment values, personal data, repository URLs, account/workspace/project/environment IDs, or local paths (`PRIVACY_EMAIL`, `PRIVACY_RENDER_API_KEY`, `PRIVACY_AWS_ACCESS_KEY`, `PRIVACY_PRIVATE_KEY`, `PRIVACY_LOCAL_PATH`).
