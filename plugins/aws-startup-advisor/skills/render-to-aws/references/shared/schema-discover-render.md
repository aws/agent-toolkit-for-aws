# Render discovery contract

Discovery consumes only structurally validated Blueprint output, active attempt-bound sanitized CLI/REST captures, the closed application scan, and the closed billing aggregate. Blueprint/application/billing-only discovery uses a deterministic local identity and null Render workspace/consent/ownership fields; it never claims live authentication. Current live operational configuration wins over Blueprint declaration, while Blueprint wins for declared repository/build/topology intent and over application inference. Utilization comes only from metrics and spend only from billing. Every differing retained field produces a closed drift record with both values, both sources, the selected winner, and a stable precedence reason.

Canonical resources use `schema-render-resource-inventory.json`; clusters use `schema-render-resource-clusters.json`. All resources are accounted exactly once as inventory entries and then appear in one cluster or the explicit unclustered list. Transport absence (`null`, `[]`, `{data:[]}`), lifecycle evidence (serving versus newest deploy, cron build versus run, instance/cold-wake state), metric outcome, and provenance remain distinct. A Blueprint persistent disk that omits `sizeGB` takes the pinned schema default of 10 GB; the disk configuration and its `service_to_disk` edge carry `sizeGB_provenance` as `schema_default` for that case and `declared` whenever the size was written explicitly or captured live.

Secret values, connection information, arbitrary event or log bodies, source snippets, account email, dashboard/SSH addresses, database rows, and Key Value contents are prohibited. Any attempt, ownership, digest, envelope, capability, bound, duplicate, collision, or accounting mismatch fails before either canonical output is replaced.
