# Troubleshooting — Dataset Quality Evaluation

## Common Errors

| Error | Cause | Fix |
|-------|-------|-----|
| Client-side schema validation error with `version=2.0.0` and `EvaluationName: Field required` | `schema_version` is not pinned, so the SDK validated against 2.0.0 | Add `schema_version="3.0.0"` to `DatasetJobConfig` |
| Schema validation error naming `EvaluationName`, `Deterministic`, `LLMAsJudge`, `Specification`, or `Metrics` | A request in an older shape: 3.0.0 has no `EvaluationName` and takes only `EvaluationConfig.Operations` | Rebuild the request as `Operations` entries (`references/dataset-service-api.md`); name the job with `base_job_name` |
| `EvaluationConfig contains unsupported field: ...` | A key beside `Operations` in `EvaluationConfig` | Move every operation into the `Operations` list |
| `InputDataConfig[0].DatasetArn is required` / `InputDataConfig is required for evaluation jobs` (through the SDK, a client-side validation error first) | The dataset quality evaluation CreateJob request is missing `DatasetArn` | Pass `input_data_config=[{"DatasetArn": DATASET_ARN}]` with a valid Hub Dataset ARN |
| `... must name a Role. <metric> takes Roles: [...]` / `... must be a non-empty list of {Role, Column} entries` / `... binds unknown Role` / `... does not bind required Role` | A View entry without `Role`, a View in another form (a bare column, a column list, a `{Role: column}` map), or a Role the metric does not declare | Use `[{"Role": "<role>", "Column": "<col>"}]` with the Role the error names (also in `supported-metrics.md` or `on-request-metrics.md`); Role names are case-sensitive |
| `... Role '<role>' must bind exactly one Column but binds N` | Several columns on a one-column Role (`Text`) | One entry per column instead: a separate operation for each column |
| `... metric effectiveness takes no View; remove Config.View` | A View on a metric that reads no columns | Send `{"Operator": "effectiveness"}` |
| `... names reserved Column 'dq_input__...'` | A View naming a column the service derives | Omit the View to run on the derived text, or bind a column of the dataset |
| `... contains unsupported operator: ...` | A name that is not a metric or keyword | Use a name from `supported-metrics.md` or `on-request-metrics.md`, or `default_metrics` / `spec_eval` / `exploratory_analysis` |
| `'<metric>' is an LLM-as-judge metric, which JobConfigSchemaVersion 3.x does not run` | A judged metric (relevance, accuracy, …) requested as an operator | Put those requirements in the spec (`quality-job.md` Step 10) |
| `... default_metrics takes no Config` / `... exploratory_analysis takes no Config` | A `Config` on a keyword that takes none | Drop `Config`; to choose columns or settings, list the metrics individually |
| `... contains default_metrics more than once` (or `spec_eval`, `exploratory_analysis`) | A keyword listed twice | List each keyword once; one `spec_eval` per job |
| `... requires SpecS3Uri ... or CodeArtifactS3Uri ...` / `... must not contain both SpecS3Uri and CodeArtifactS3Uri` | A `spec_eval` naming neither or both sources | Name exactly one; for a synthetic-dataset-generation (SDG) dataset, pass the generation spec's `SpecS3Uri` explicitly |
| `EvaluationConfig.Operations[i].Config... contains unsupported field: <key>` / `... contains unsupported model: <id>` on a `spec_eval` | A key `spec_eval` does not take (a misspelling, a lowercase name, `TargetTokensPerMinute`), or a model outside the spec model list | Keep only the keys of the `spec_eval` Config table in `references/dataset-service-api.md` Spec-driven evaluation; `ContextDocumentsS3Uri` is one of them, and dropping it fails a job whose spec has `context: documents` criteria with `CONTEXT_REQUIRED_NO_DOCUMENTS`. Pick a model from that section's "Model" list |
| `... contains duplicate operation: <metric>` | The same metric with an identically written `Config` twice | Remove the repeat, or change its View or settings |
| Job fails with `ClientError: The job failed due to invalid input or configuration. Verify your request parameters and input data.. Check CloudWatch Logs: log-group=..., stream=...` | A request or data error the evaluation found while running; every one shows this reason | Read the log stream the `FailureReason` names for the specific message; the rows marked "Job log:" below name the causes |
| Job log: `Metric '<metric>' ... is requested more than once with the same View and params` | A repeat the service finds at run time: the same run written two ways (a setting at its default next to the same metric without it, or no `Config` next to `"Config": {}`), or a default-set metric without a View and with its default settings next to `default_metrics` | Remove the repeat (`dataset-service-api.md` → repeats caught only at run time) |
| Job log: `Metric '<metric>' ... would write the same per-row column(s) as another run` | Two runs of a row-writing metric on the same column, even with different settings | Keep one run per column; only aggregate-only metrics take different settings on one column |
| Job log: `... requires Role '<Role>', but the detected format has no default column for it` | A `Column` or `Label` metric without a View | Bind its columns in a View |
| Job log: `No column mapping (View) was given, and no default could be inferred for the detected dataset format '<fmt>'` | `default_metrics`, or a metric without a View, on Custom or Nova_RLVR data, which have no default columns | List each metric with an explicit View |
| Job log: `View binds Column '<col>', but it is not present in the dataset records` (`exact_dedup` / `fuzzy_dedup`: `SMOC_REQUIRED_COLUMN_MISSING`) | A View naming a column the records do not have; on a chat format, `prompt` / `completion` | Bind a column of the dataset, or omit the View on a `Text` metric to run on the derived text |
| `HUB_FINALIZATION_FAILED` | The service could not publish the job's `metadata.json` or record the result on the dataset, for example because the role cannot write to the output prefix or use its KMS key | Check the role's `s3:PutObject` and KMS permissions on the output prefix, then resubmit; the job has no `MetadataS3Uri`, and `scripts/dq_job_output.py` finds whatever it wrote |
| `... references a Dataset entity with schema version ... requires schema version 4.0.0 or later` | Dataset was imported with an old schema (v2.0.0) | Register the dataset again with the generated notebook's Cell 7 (the SDK's `DataSet.create` writes schema 5.0.0; `references/dataset-import.md`) and send the new version's ARN as `DatasetArn` |
| `object instance has properties which are not allowed by the schema: ["RoleArn"]` | The role was set on the `DatasetJobConfig` (`dq_config.role_arn`), so it went into the `JobConfigDocument` | Pass the role on `DataPreparer(role=...)` only, as the generated notebook's Cell 5 does |
| `RoleValidationError: IAM role ... cannot be used for 'training' workloads` at the dataset registration (Cell 7), for example on an Admin session | The SDK validates the registration `role` itself and refuses an identity that SageMaker cannot assume | Set `ROLE_ARN` in Cell 4 to the plan's SageMaker execution role (`references/quality-job.md` Step 11 item 3), never change the format to `Custom` |
| `ResourceInUse` on a second import under the same name, and `dataset.wait()` never returns | A `hub_name` was passed to `DataSet.create`; the SDK's version lookup and `wait()` still read the account's SageMaker AI Registry | Pass no `hub_name`, as the generated notebook's Cell 7 does (`references/dataset-import.md`, "Where it registers") |
| `ResourceLimitExceeded: Cannot create more than 2000 DataSets` | The account's SageMaker AI Registry has reached its dataset limit | Remove registrations the user no longer needs (`references/dataset-import.md`, "Removing a registration"). There is no hub choice: the SDK registers into the account's SageMaker AI Registry only |
| `ResourceNotFound: Hub with name AIRegistry does not exist` | A call named the hub by the literal string `AIRegistry`. The account's SageMaker AI Registry has a hashed name the SDK derives from the region and the account; its display name is `AiRegistry-<region>-<account>` | Let the generated notebook's Cell 7 register the dataset: the SDK's `DataSet.create` resolves the hub and creates it when the account has none. For a `describe-hub-content` or `delete-hub-content` call, read the hub name from the Dataset ARN. Do not pre-run `create-hub --hub-name AIRegistry` |
| Hub import: Schema validation failed, missing required properties | A hand-written import call that passes its own `HubContentDocument` | Do not write an alternative import. The generated notebook's Cell 7 calls the SDK's `DataSet.create`, which writes the 5.0.0 document itself (`references/dataset-import.md`, "What the SDK writes") |
| `Multiple JSONL files found under s3://…/byod: [...]` | A shared prefix (`byod/`) was registered instead of one file; the job scans the whole prefix | Regenerate the notebook: Cell 6 uploads to `byod/<HubContentName>/<filename>` and Cell 7 registers that one file's key with the SDK's `DataSet.create`, never a folder |
| `InternalServerError: The job failed due to an unexpected error. ... Check CloudWatch Logs: log-group=/aws/sagemaker/Job/DataQualityEvaluation/, stream=...` | An unexpected error during the evaluation | Read the log stream the `FailureReason` names. It may point to a stale dataset (S3 data deleted) or a format mismatch; otherwise report it |
| Job log: `l3_category has N null... labels`, then `InternalServerError`, on a `taxonomy` job | The input is too small for a three-level tree: on a few dozen rows the operator built only two levels and failed at finalization. The failure is deterministic for the input, so the same job resubmitted unchanged fails the same way | Do not retry it unchanged. Tell the user taxonomy is built for larger corpora and offer to run on a larger dataset or with fewer framings (`taxonomy/overview.md` Prerequisites) |
| `UnrecognizedClientException: security token invalid` | AWS credentials expired | Refresh your AWS credentials — e.g. `aws sso login` (or `aws sso login --profile <profile>`), or re-export the access key/secret/session token for your profile |
| A `Completed` job has no `MetadataS3Uri` | The dataset's Hub entry was deleted while the job ran, so the service did not publish the job's result | Find the outputs with `scripts/dq_job_output.py` (its `output_folder`) |
| Output files not where expected | Each job writes to a folder of its own under `S3OutputPath`, named by the service | Never build the path or search a listing for the job name. For a completed job read `JobConfigDocument.MetadataS3Uri` (`aws sagemaker describe-job --job-name <job-name> --job-category DataQualityEvaluation`); that `metadata.json` lists every output's S3 URI under `Reports`. For a running job use `scripts/dq_job_output.py` (`references/progress-check.md`) |
| `ValidationException: ... does not satisfy the configuration schema for metric language_detection` | `languages` holds an uppercase (`EN`), unsupported, or repeated code, or is empty; or `min_score` is outside [0, 1]; or a key other than `languages` / `min_score` | Use lowercase lid.176 codes exactly as the model emits them (`en`, `fr`, `ast`), omit `languages` instead of sending `[]`, and keep the parameter names lowercase |
| Job log: `Metric 'language_detection' requires a View that binds one flat text Column` / `cannot bind Column 'messages'` / `evaluates one flat text column, but row N ...` | No View (it never default-binds), the View names a chat field, or the bound column holds lists or objects | Bind one top-level column of plain strings with `{"Role": "Text", "Column": "<col>"}`; for chat data, materialize a flat text column first (dataset-transformation) |
| `ValidationException: ... does not satisfy the configuration schema for metric pii_detection` | A key besides `View` in its `Config` (it takes no parameters), e.g. `DefaultAction` / `ActionMap`, which belong to the dataset-transformation `PiiRedaction` operator | Send only `{"View": [...]}`; choose redaction actions later, in `PiiRedaction` |
| A job with `pii_detection` fails | Its View binds neither or both of Role `Messages` / Role `Text` (it never default-binds) | Bind exactly one: `{"Role": "Messages", "Column": "<chat column>"}` or `{"Role": "Text", "Column": "<text column>"}` |
| A job with `exploratory_analysis` ends `Failed` with `FailureReason` `INTERNAL_ERROR` | The exploratory analysis failed or wrote no findings: `aggregate/exploratory/findings.json` missing, or not a non-empty JSON array (empty, `[]`). Either fails the whole job, whatever else it ran, and the job gets no `MetadataS3Uri` | Report the failure. Offer to resubmit without `exploratory_analysis`, which reruns the other operations as a new billed job, or the client-side exploratory analysis (`references/exploratory-analysis.md`) instead |

### Validation rules checked at submit time (400 error)

Check these before submitting a request; each one is rejected with a 400 and the request never becomes a job.

- An empty `Operations` list, or a key beside `Operations` in `evaluation_config`, is rejected.
- Unknown operator names are rejected, and so are judged metrics (relevance, accuracy, and the like).
- A keyword listed twice, or a `Config` on `default_metrics` / `exploratory_analysis`, is rejected.
- View errors are rejected: an entry without `Role`, a Role the metric does not declare, a missing required Role, several columns on a one-column Role, a View on `effectiveness`, or a `dq_input__` column; the error names the Roles to use.
- Duplicate runs (the same operator with an identically written `Config`) are rejected.
- `language_detection` is rejected when `languages` holds an uppercase, unsupported, repeated, or `unknown` code or is an empty list, when `min_score` is outside [0, 1], or when its `Config` holds any other key (including `Languages` / `MinScore`); the message is `"does not satisfy the configuration schema for metric language_detection"`.
- `pii_detection` is rejected when its `Config` holds any key besides `View` (including the dataset-transformation keys `DefaultAction` / `ActionMap`); the message is `"does not satisfy the configuration schema for metric pii_detection"`.
- `spec_eval` is rejected for any key outside its Config table in `references/dataset-service-api.md` Spec-driven evaluation (`"contains unsupported field"`; `ContextDocumentsS3Uri` is in the table), for a model outside the list in the same section, "Model" (`"contains unsupported model"`), and for a `SpecS3Uri` that is not a `.md` / `.txt` file.

### Validation rules checked at run time (job failure)

Every one of these fails the job with a `FailureReason` that starts with `ClientError: The job failed due to invalid input or configuration.` and names the CloudWatch log stream. The messages below are in that log, so check these before submitting.

- Column typos fail the job: `"View binds Column 'nope', but it is not present in the dataset records"` (for `exact_dedup` / `fuzzy_dedup` the message is `"SMOC_REQUIRED_COLUMN_MISSING: A bound input column is missing."`).
- Duplicates the service finds only at run time fail the job with `"is requested more than once with the same View and params"`: the same run written two ways (a setting at its default next to the same metric without it, or no `Config` next to `"Config": {}`), or a default-set metric without a View and with its default settings next to `default_metrics`.
- Two runs of a metric that writes row columns on the same column, even with different settings, fail the job with `"would write the same per-row column(s) as another run"`.
- A `Column` or `Label` metric without a View fails the job with `"requires Role '<Role>', but the detected format has no default column for it"`.
- `default_metrics`, or any metric without a View, on Custom or Nova_RLVR data fails the job with `"No column mapping (View) was given, and no default could be inferred for the detected dataset format"`.
- `language_detection` without a View, bound to `messages` / `conversations`, or bound to a column holding nested values fails the job with `"Metric 'language_detection' requires a View that binds one flat text Column"` / `"cannot bind Column 'messages'"` / `"evaluates one flat text column, but row N ..."`.
- `pii_detection` with no View, or with a View binding both `Messages` and `Text`, fails the job.

## Request behavior

Only the listed operations run. `default_metrics` adds the format's default set; without it, default metrics (including row-level `word_count`, `character_count`) run only if listed. The evaluated_data.jsonl will have no deterministic `dq_` output columns if only dataset-level metrics are requested.

**Schema version:** the request pins `schema_version="3.0.0"` on `DatasetJobConfig`; why, and the error an unpinned request fails with, are `references/dataset-service-api.md` "Dataset Quality Evaluation", its **Important** list (the symptom is the first row of Common Errors above).

**Metric naming:** Use the catalog operator names (`word_count`, `character_count`, `uniqueness`, `toxicity`, etc.); `word_length`, `character_length` and `toxic_samples` are not operators.

**Output columns:** Row-level output uses the pattern `dq_<metric>__<column>` (double underscore + the bound column, lowercased, each run of characters other than letters and digits replaced by `_` and any leading or trailing `_` dropped), with the metric's row-column name: `dq_word_count__answer`, `dq_toxicity_label__question`. A run without a View has the derived column as its suffix: `dq_word_count__dq_input__completion` (`output-schema.md`).

**Do not send `EvaluationConfigSchemaVersion`**; the service rejects it.

To run the deterministic defaults, send `{"Operations": [{"Operator": "default_metrics"}]}`.
