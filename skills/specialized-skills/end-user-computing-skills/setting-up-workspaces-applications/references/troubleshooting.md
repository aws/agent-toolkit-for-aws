# Provisioning Troubleshooting

Match on the error, then apply the fix. These are **control-plane** (provisioning) failures — for connection/runtime errors on a built desktop (`dcv session not ready`, `client_disconnected`, 401/403), see the `amazon-workspaces-agent-access` skill's troubleshooting reference.

## Error → cause → fix

| Error | Cause | Fix |
|---|---|---|
| `ResourceAlreadyExistsException` | A fleet/stack with that `Name` already exists — possibly from a prior retry (create ops take no idempotency token). | Describe the existing resource. If it matches the intended config, converge (continue with it); if not, pick a new name or update the existing resource. Do not blind-retry creates. |
| `LimitExceededException` on `CreateFleet` | Account service quota reached — graphics-instance quotas default to **0** in new accounts, and fleet-count / total-streaming-instance quotas bite in trial accounts. | Check Service Quotas for the specific limit and request an increase (not instant — plan for the delay). For trials, use a `stream.standard.*` type with available quota. |
| `InvalidParameterCombinationException` | Conflicting fields — e.g. `DisconnectTimeoutInSeconds: 0` (rejected; minimum 60), `MaxUserDurationInSeconds` not greater than `IdleDisconnectTimeoutInSeconds`, `ComputeCapacity` on an Elastic fleet, or multi-session fields on a single-session fleet. | Re-check values against the accepted ranges in fleet-stack-recommendations.md and the [CreateFleet API reference](https://docs.aws.amazon.com/appstream2/latest/APIReference/API_CreateFleet.html). For the timeout rule: raise the max duration above the idle timeout, or set the idle timeout to 0. |
| CLI/SDK `ParamValidationError` / "Unknown parameter" / unknown flag before the call is sent | The installed CLI or SDK bundles an AppStream model that predates a newer API field (e.g. `AgentAccessConfig.UserControlMode`, `--disable-imdsv1`, `--agent-access-config` on `create-image-builder`, or the `update-image-builder` command), so it's rejected client-side even though the API supports it. | Upgrade the AWS CLI or `boto3`/`botocore` and retry. If `aws --version` still shows the old version after the upgrade, an older `aws` comes first on `PATH`: find every copy with `which -a aws` (macOS, Linux) or `where.exe aws` (Windows), and remove the old one or put the new one first. **If two or more fields get rejected in one sequence, stop adapting call-by-call and recommend the upgrade first** — it fixes all of them at once. If upgrading isn't possible right now, drop only the rejected fields, complete the sequence, tell the user exactly which settings were skipped, and set them afterwards via the console or an upgraded CLI (`update-stack`/`update-fleet`). |
| Streaming URL shows "agent-enabled session is not allowed for viewing" | The stack has `AgentAccessConfig` but `UserControlMode` is unset or `DISABLED` — human viewing of agent sessions is blocked unless it's `VIEW_ONLY` or `VIEW_STOP`. Commonly caused by the stale-SDK row above: an older CLI dropped the field at create time. | Set it with `update-stack` (`AgentAccessConfig.UserControlMode: VIEW_STOP`) using a current CLI/SDK, then mint a fresh streaming URL. To watch a specific agent's live session, the URL must use that agent's UserId (see user-access.md). |
| `Your AWS account does not own the S3 bucket '<bucket>' or the AppStream 2.0 service does not have s3:ListBucket permission to access this bucket.` | The screenshot bucket belongs to another account, or its policy doesn't let `appstream.amazonaws.com` list it. | Use a bucket in this account and add the service-principal `s3:ListBucket` statement from [agent-access-config.md](references/agent-access-config.md). |
| `Your AWS account does not own the S3 bucket '<bucket>'.` | No bucket by that name exists. | Create the bucket first, or correct the name. |
| `The specified S3 bucket '<bucket>' does not exist in the <region> AWS Region.` | The screenshot bucket is in another Region. | Use a bucket in the same Region as the stack or image builder. |
| `S3BucketArn is required when ScreenshotsUploadEnabled is true.`, `S3BucketArn is required when ReplaySessionEnabled is true.`, `S3BucketArn is only supported when ScreenshotsUploadEnabled or ReplaySessionEnabled is true.` or `S3BucketArn is not allowed when ScreenshotsUploadEnabled is not true.` | A feature that writes to the bucket is on without `S3BucketArn`, or the bucket is set with neither feature on, counting what an update merges with the stored configuration. The last message is the one an account without Replay Session gets. | Set `S3BucketArn` together with `ScreenshotsUploadEnabled`, `ReplaySessionEnabled`, or both, or remove all of them. Without Replay Session, turning `ScreenshotsUploadEnabled` off clears the bucket. |
| `ReplaySessionEnabled requires the COMPUTER_VISION agent action to be ENABLED.` or `KmsKeyArn is only supported when ReplaySessionEnabled is true.` | Replay Session captures screenshots, so it needs vision; `KmsKeyArn` is only for Replay Session. | Enable `COMPUTER_VISION`, or drop `KmsKeyArn` when Replay Session is off. |
| `The specified ComputerUseInterfaceId is not supported.` or `The ComputerUseInterface feature is not enabled for this account.` | An unknown interface ID, or an account that doesn't have computer use interfaces enabled. | Use a supported ID (the `amazon-workspaces-agent-access` skill lists them), or leave the field unset. |
| `The image builder <name> cannot be updated while it is RUNNING.` | `update-image-builder` runs only on a `STOPPED` builder. | `stop-image-builder`, poll until `STOPPED`, update, then `start-image-builder`. |
| `AgentAccessConfig is only supported on Windows image builders.` or `AgentAccessConfig is not supported on domain-joined image builders.` | Agent access on a Linux or domain-joined builder. | Use a Windows builder that isn't domain-joined, or have the user install the apps without agent access. |
| `IncompatibleImageException` when adding agent access to an image builder | The image's WorkSpaces Applications agent is too old for agent access. | Launch the builder from a current public base image with `--appstream-agent-version LATEST`, or patch the image with `create-updated-image`. |
| `CreateFleet` fails: instance type not available / not supported in the Availability Zone | The chosen instance type isn't offered in the selected subnets' AZs. | Pick subnets in AZs where the instance type is available, or choose a different instance type. There is no public per-AZ availability API for `stream.*` types — retry with other subnets from the discovery step and tell the user why. |
| `ResourceNotFoundException` on `AssociateFleet` | Stack or fleet name wrong, or creation didn't complete. | Verify both exist with `DescribeStacks` / `DescribeFleets`; create order is fleet and stack before association. |
| `ConcurrentModificationException` / `ResourceInUseException` | Another operation is in flight on the resource. | Back off and retry; serialize operations on the same resource. |
| `IncompatibleImageException` | Image doesn't support the requested platform/instance family — commonly GPU vs non-GPU mismatch. | Pick an image built for the target family, or change the instance family (note: GPU↔non-GPU is effectively a rebuild). |
| Fleet stuck `STARTING`, or `RUNNING` with `Available: 0` | Instances still provisioning, subnet capacity/IP exhaustion, or image issues surfaced in `FleetErrors`. | Poll `DescribeFleets` and read `FleetErrors`. Verify the subnets have free IPs and span two AZs. RUNNING alone isn't ready — wait for `ComputeCapacityStatus.Available > 0`. |
| Human user gets "user does not exist" at sign-in | User-pool emails are **case-sensitive at login** — capitalization must match the address used at `create-user`. | Have the user sign in with the exact original capitalization, or recreate the user. |
| Human user's temporary password expired | The welcome email's temporary password is valid for **7 days**. | Resend: `aws appstream create-user --user-name <email> --authentication-type USERPOOL --message-action RESEND` (omit first/last name with RESEND). |
| `BatchAssociateUserStack` returns errors for a user | The stack's fleet is domain-joined (user-pool users can't be assigned to domain-joined stacks), or the user/stack name is wrong. | Domain-joined setups are SAML-only and outside this guided flow — route to the docs. Otherwise verify the user exists and the stack name. |
| Insufficient capacity at session time | Max capacity below peak concurrent demand (1 instance = 1 session), or scale-up lag on scale-from-zero fleets. | Raise max capacity / warm minimum via Application Auto Scaling; for bursty patterns, scale up ahead of the window. |
| No usable VPC/subnets at create time | Account has no default VPC (common), or subnets don't span two AZs. | Network creation is admin-owned — stop and hand off rather than creating VPCs silently. See create-workspace.md pre-create checks. |
| `UnauthorizedOperation` or `AccessDeniedException` on a describe call (for example `ec2:DescribeVpcs`) | The caller can't read that resource, so the value can't be discovered. | Name the missing action, ask the user for the value it would have found, and continue. Don't guess it (create-workspace.md, pre-create checks). |
| `FAILED_TO_INSTALL` for a license-included application in `describe-software-associations` | The deployment to the image builder failed. | Read its `DeploymentError`, then retry with `start-software-deployment-to-image-builder --retry-failed-deployments`. Check that every application uses one version and one architecture, and that the version supports the image's Windows Server version on the license-included applications page (image-setup.md). |
| IAM `AccessDenied` on create/scale calls | Caller lacks `appstream:*` create permissions, or Application Auto Scaling lacks its service-linked permissions for fleets. | Grant the specific `appstream` actions the flow performs; for scaling, see [Fleet Auto Scaling](https://docs.aws.amazon.com/appstream2/latest/developerguide/autoscaling.html) prerequisites. |

## General rules

- **Read `FleetErrors`** on `DescribeFleets` — provisioning failures usually explain themselves there.
- **Converge, don't loop:** `ResourceAlreadyExists` means describe-and-continue; `ConcurrentModification` means back off; a parameter error means fix the value — retrying unchanged won't help.
- **Quota and network problems are admin problems** — surface them with the specific ask (quota increase for family X; two subnets in different AZs) instead of working around them.
